# Stash CLI 需求

## 概要

构建一个交互式本地终端版 Stash：不启动 Stash server，也不依赖 Stash HTTP API，即可打开或创建本地 Stash-like SQLite 数据库。第一版重点覆盖配置目录扫描、封面网格浏览、底部 slash-command 输入、可配置元数据显示，以及轻量 scene 标记/编辑；远程媒体通过本机挂载路径访问。

---

## 问题背景

Stash Web UI 需要运行 server 和浏览器，但有些使用场景更适合快速、本地、键盘驱动的终端界面。CLI 应让用户在 Kitty 或 Ghostty 中浏览媒体库；如果媒体实际位于另一台机器上，用户先通过 `sshfs`、NFS、SMB 等方式挂载到本机，CLI 再像访问本地文件一样处理。

第一阶段需要验证本地建库、目录扫描、终端浏览、搜索过滤和直接数据库访问。完整元数据管理、完整扫描 parity 和内置 SSH/SFTP backend 放到后续阶段。

---

## 关键决策

- **打开或创建本地数据库。** 第一版既可以连接现有 `stash-go.sqlite`，也可以在配置媒体目录后创建本地 Stash-like SQLite 数据库。
- **Stash server 必须关闭。** CLI 写入数据库时需要独占访问，避免和 Stash server 并发写同一个 SQLite 文件。
- **封面网格是主体验。** Kitty-compatible 终端默认显示封面网格；不支持或不稳定时自动降级为纯列表。
- **交互搜索是核心能力。** 浏览时必须能按 scene 名称、tag、performer 等元数据快速过滤。
- **底部命令输入栏是主要控制面。** TUI 底部必须提供 slash-command prompt，支持 `/search <query>`、`/scan <path>` 这类命令。
- **远程媒体先挂载。** 远程文件通过 `sshfs`、NFS、SMB 或其他方式暴露成本机路径；CLI 第一版不内置 SSH/SFTP 文件 backend。
- **启动扫描是基础能力。** CLI 启动时可以扫描配置的本地或挂载远程目录，并更新本地 SQLite 数据库。
- **轻编辑先行。** 初始写入能力只覆盖单个 scene 的轻量字段，tag、performer、studio 和文件管理后续再做。

---

## 参与者

- A1. **CLI 用户。** 在本机运行终端应用，选择或创建 Stash 数据库，浏览视频，并执行轻量编辑。
- A2. **本地 Stash-like 数据库。** 保存 scene 记录、文件路径、生成资源和元数据。
- A3. **挂载媒体源。** 通过普通文件系统路径提供本地或远程视频访问。
- A4. **终端渲染器。** 决定应用能否显示 Kitty graphics 封面网格，或必须降级为列表模式。

---

## 需求

**启动与数据库访问**

- R1. CLI 必须在不启动 Stash HTTP server、也不访问 Stash API 的情况下运行。
- R2. CLI 必须从 `config.toml` 读取数据库路径，例如 `database_path`。
- R3. CLI 必须在写操作前确认自己可以安全地独占数据库。
- R4. CLI 必须能打开已有兼容数据库，或在配置允许初始化时创建新的本地 SQLite 数据库。
- R5. 当数据库路径不可读、不兼容或无法创建时，CLI 必须显示清晰的启动错误。

**扫描与索引**

- R6. CLI 必须从 `config.toml` 读取媒体目录配置。
- R7. 当启用启动扫描时，CLI 必须扫描配置的本地目录或挂载远程目录。
- R8. 扫描必须把发现的视频文件加入本地数据库，并保存足够用于浏览的元数据，包括名称/路径，以及可获取时的 duration。
- R9. 当媒体文件可读时，扫描应该为封面网格生成或发现可用封面。
- R10. 扫描必须把挂载远程目录视为本地目录处理，并且不要求 SSH 凭据。

**浏览体验**

- R11. 在支持图形的终端中，默认视图必须是视频封面网格。
- R12. 每个网格项必须显示可配置元数据字段，初始字段包括 name、duration 和 date。
- R13. 当终端图形能力不存在或不稳定时，CLI 必须提供纯列表降级模式。
- R14. 用户必须能从网格或列表打开选中视频的详情视图。
- R15. CLI 必须是交互式 TUI，支持键盘导航、搜索输入、结果更新，以及无需重启即可清除或细化过滤条件。
- R16. CLI 必须支持按 scene 名称、tag 和 performer 搜索或过滤，包括 actress 风格的 performer 搜索。
- R17. CLI 必须提供持久的底部输入栏，用于输入带参数的 slash commands。
- R18. Slash commands 必须可发现，至少通过 help 或 completion 让用户了解可用命令。
- R19. Slash command 错误必须在 TUI 内显示，不能退出应用，也不能破坏当前视图。

**媒体与生成资源**

- R20. CLI 必须把挂载远程媒体路径当作本地路径处理。
- R21. 第一版不得要求内部 SSH 或 SFTP 配置。
- R22. 当已有 Stash 生成封面可用时，CLI 应优先使用这些资源。
- R23. 当缺少封面但媒体文件可读时，CLI 可以生成本地预览缓存，但不得修改媒体文件本身。

**轻量编辑**

- R24. 第一版写入能力必须支持 favorite、watched、rating、organized、title、date 等轻量 scene 字段。
- R25. CLI 必须在用户返回浏览前显示编辑成功或失败状态。
- R26. 第一版不得包含 tag、performer、studio、scraper 或文件删除工作流。

**配置**

- R27. CLI 必须允许用户在 `config.toml` 中配置网格或列表展示的元数据字段。
- R28. CLI 必须允许配置图形偏好，至少支持自动检测和 list-only 模式。
- R29. CLI 必须允许在 `config.toml` 中开启或关闭启动扫描。
- R30. CLI 必须把用户级缓存和配置文件放在 Stash 媒体目录之外。

## 关键流程

- F1. **打开已有库**
  - **触发：** 用户启动 CLI。
  - **参与者：** A1, A2
  - **步骤：** CLI 读取 `config.toml`，打开配置的 SQLite 数据库，验证可以读取浏览记录，然后进入默认视图。
  - **结果：** 用户看到封面网格或降级后的列表视图。
  - **覆盖：** R1, R2, R5, R11, R13

- F2. **初始化并扫描媒体库**
  - **触发：** 用户启动 CLI，配置里包含数据库路径和媒体目录。
  - **参与者：** A1, A2, A3
  - **步骤：** CLI 在需要时创建本地数据库，扫描配置目录，写入发现的视频，并准备浏览所需元数据。
  - **结果：** 用户不必先通过 Web UI 创建 Stash 数据库，也能得到可浏览的视频库。
  - **覆盖：** R4, R6, R7, R8, R9, R10

- F3. **交互式搜索媒体库**
  - **触发：** 用户在浏览时输入搜索词或元数据过滤条件。
  - **参与者：** A1, A2
  - **步骤：** CLI 按 name、tag 或 performer 过滤可见 scenes，并在当前网格或列表中刷新结果。
  - **结果：** 用户可以快速缩小媒体库范围，并继续清除或细化搜索。
  - **覆盖：** R15, R16

- F4. **运行底部 slash command**
  - **触发：** 用户在 footer prompt 输入 slash command 和可选参数。
  - **参与者：** A1
  - **步骤：** CLI 解析命令，校验参数，执行请求动作，并在原地显示成功或错误。
  - **结果：** 用户可以在不离开当前 TUI 的情况下驱动搜索、扫描、视图切换和轻量编辑。
  - **覆盖：** R17, R18, R19

- F5. **浏览挂载远程媒体**
  - **触发：** 数据库中存在指向挂载远程目录的文件路径。
  - **参与者：** A1, A2, A3
  - **步骤：** CLI 显示数据库中的 scenes，并在需要时通过本地挂载路径读取媒体或生成资源。
  - **结果：** 远程视频在浏览体验中表现得像本地视频。
  - **覆盖：** R10, R20, R21, R22, R23

- F6. **编辑 scene 标记字段**
  - **触发：** 用户修改选中 scene 的轻量字段。
  - **参与者：** A1, A2
  - **步骤：** CLI 检查写入安全性，应用编辑，报告成功或失败，并刷新可见元数据。
  - **结果：** 数据库被更新，但 Stash server 不需要启动。
  - **覆盖：** R3, R24, R25

## 验收示例

- AE1. **Kitty 封面网格**
  - **覆盖：** R11, R12, R13
  - **前提：** 用户在 Kitty 中运行 CLI，并配置了有效数据库。
  - **当：** 终端图形能力检测成功。
  - **则：** 应用打开封面网格，并在每个项目上显示配置的元数据。

- AE2. **列表降级**
  - **覆盖：** R13, R28
  - **前提：** 用户在不支持或不稳定支持图片渲染的终端中运行 CLI。
  - **当：** CLI 启动。
  - **则：** 应用进入列表模式，而不是失败或显示破损 placeholder。

- AE3. **按元数据搜索**
  - **覆盖：** R15, R16, R17
  - **前提：** 用户正在浏览封面网格。
  - **当：** 用户通过底部输入栏搜索 scene 名称、tag 或 performer。
  - **则：** 可见结果在 TUI 内更新，应用无需重启。

- AE4. **Slash command 错误**
  - **覆盖：** R17, R18, R19
  - **前提：** 用户输入未知 slash command 或无效参数。
  - **当：** 命令被提交。
  - **则：** Footer 显示可恢复错误，当前浏览视图保持完整。

- AE5. **启动扫描创建媒体库**
  - **覆盖：** R4, R6, R7, R8
  - **前提：** 配置的数据库文件不存在，并且启动扫描已启用。
  - **当：** CLI 使用一个或多个可读媒体目录启动。
  - **则：** CLI 创建本地数据库，并用发现的视频填充它。

- AE6. **挂载远程路径**
  - **覆盖：** R10, R20, R21, R23
  - **前提：** 一个 scene 指向本地挂载远程目录下的视频。
  - **当：** 用户在 CLI 中打开该 scene。
  - **则：** CLI 像处理本地文件一样处理该路径，并在文件可读时可以生成预览。

- AE7. **Server 冲突**
  - **覆盖：** R3, R24, R25
  - **前提：** Stash server 仍在使用配置的数据库。
  - **当：** 用户尝试执行轻量编辑。
  - **则：** CLI 阻止写入，并说明必须先停止 Stash server。

## 成功标准

- 用户可以不启动 Stash server，就在终端中浏览已有 Stash library。
- 用户可以只配置媒体目录，就通过 CLI 得到本地可浏览 SQLite 数据库，而不必先使用 Web UI。
- 按 name、tag、performer 搜索在典型媒体库规模下足够快，感觉是交互式的。
- Kitty 或 Ghostty 用户可以获得可用的封面网格体验。
- 不支持图片渲染的终端仍可通过稳定列表视图浏览。
- 挂载远程媒体可以工作，CLI 不需要知道 SSH 凭据。
- 常用动作可以通过底部 slash commands 完成，用户不必记忆大量单键快捷键。
- 轻量编辑足够安全，不会破坏数据库，也不会和现有 Stash server 竞争写入。

## 范围边界

**后续再做**

- 与 Stash Web scanner 完全等价的扫描能力和所有导入边界情况。
- 内置 SSH/SFTP 媒体访问。
- Tag、studio、performer、scraper 和 stash-box 管理。
- 文件删除、文件移动和其他破坏性媒体操作。
- 完整终端内视频播放。

**第一阶段之外**

- 替代 Stash Web UI。
- 作为后台服务运行。
- 正常使用时依赖 Stash HTTP 或 GraphQL server。

---

## 依赖与假设

- 用户可以提供有效的现有 Stash SQLite 数据库，或配置媒体目录供 CLI 初始化。
- 用户可以在 CLI 写入数据库前停止 Stash server。
- 远程媒体在 CLI 启动前已经挂载到本地文件系统。
- 至少一个目标终端支持 Kitty graphics；不支持或渲染失败时有列表降级。
- 需要生成预览时，FFmpeg 或已有 Stash 生成资源可用。
