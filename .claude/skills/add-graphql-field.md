# Add a New GraphQL Field

Step-by-step guide for adding a new field to the GraphQL API.

## When to use
- Adding new data fields to existing types
- Creating new queries or mutations
- Extending the API surface

## Steps

### 1. Modify the GraphQL schema

Edit the relevant `.graphql` file in `graphql/schema/`:

- `schema/types/` — Type definitions (Scene, Performer, Studio, etc.)
- `schema/queries/` — Query definitions
- `schema/mutations/` — Mutation definitions

Example — adding a field to an existing type:
```graphql
# In graphql/schema/types/scene.graphql
type Scene {
  # ... existing fields ...
  myNewField: String
}
```

### 2. Regenerate code

```bash
make generate
```

This updates:
- Go resolver interfaces in `internal/api/`
- Go model types in `internal/models/`
- TypeScript types and hooks in `ui/v2.5/src/core/`

### 3. Implement the resolver

Find the resolver file in `internal/api/` — it will now have a new method that needs implementation. The generated code will have a placeholder that returns an error.

Resolver files follow the pattern: `internal/api/resolver_*.go` or `internal/api/scene_resolver.go`

### 4. Update database layer (if needed)

If the field requires database changes:
1. Add the column in `pkg/sqlite/migrations/` (new migration file)
2. Update the model in `internal/models/`
3. Update the repository in `pkg/sqlite/`

### 5. Update the frontend

Use the generated TypeScript hooks in `ui/v2.5/src/core/`:

```typescript
import { useSceneQuery } from "src/core/StashService";
```

### 6. Validate

```bash
make validate
```

## Important notes
- NEVER edit generated files directly — they are overwritten on `make generate`
- Generated Go files typically have `// Code generated by github.com/99designs/gqlgen, DO NOT EDIT.`
- Always run `make generate` after any schema change before building
- Database migrations must be forward-only (no down migrations in production)
